# OpenCode 接入三项目 — 实现任务书（派工契约）

> 文书性质：**派工与验收契约**，回答「谁做什么、做到什么程度算完、如何被审查」。论证依据见《opencode接入三项目-实现计划书》（下称《计划》）——本任务书的每条要求都可回指《计划》的对应论证，不再重复论证本身。
> 执行架构：**开发全部由子代理执行；主代理只做三方六维度审查监控。**
> 硬前提：《计划》第二节的重验事实是唯一事实基线；实现中发现事实不符，立即上报而非就地猜测。

---

## 一、三方六维度审查监控框架

### 三方（三个角色，职责互斥）

| 角色 | 承担者 | 职责 | 禁止 |
|------|--------|------|------|
| 第一方：实现 | 开发子代理（每批次一个） | 按工作包改代码、逐层自验、产出变更说明与证据 | 不得自行放宽验收标准；不得跳过自验 |
| 第二方：交叉审查 | 审查子代理（独立于实现者） | 六维度盲审：不采信实现代理的解释，只核 diff 与证据 | 不得代写修复代码；不得以「看起来对」放行 |
| 第三方：终审监控 | 主代理 | 裁决两方分歧、把关放行/退回、监控全局 | 不亲自写业务代码（审查性验证命令除外） |

### 六维度（每维度一句话判据 + 不通过判据）

| # | 维度 | 通过判据 | 不通过判据（示例） |
|---|------|----------|--------------------|
| 1 | 正确性 | 改动的因果逻辑与《计划》一致，且真实切断了目标因果链 | 只换了字面量未接身份事实源；判据子串误伤 |
| 2 | 完整性 | 七层中属本批次的层全部落地，六条链无缺口 | 遗留某处 claude 字面量未按引擎分派 |
| 3 | 一致性 | 三项目间命名、字段、优先级规则一致（如 engine 取值域、回退链） | launcher 与 pipeline 对 engine 缺省值理解不同 |
| 4 | 影响面与零回归 | claude 行为逐字等价有证据；不属本批次的链零触碰 | claude 分支被「顺手重构」；codex 岛被改动 |
| 5 | 实证性 | 每条验收都附真实运行证据（捕获帧/输出摘录），非口头声明 | 无证据的「已验证」；证据与声明不符 |
| 6 | 防退化 | 失配路径显式报错；无静默假阴/假闲；判据集中参数化 | 判据散点 if；失败吞掉默认放行 |

审查流程：实现交付 → 交叉审查逐维度出结论（通过/不通过+精确位置+理由）→ 不通过项退回实现修复 → 复审 → 主代理终审裁决放行。

## 二、工作包 T1（批次一：五链同级）

**范围（对应《计划》第 1–5、7 层）**：引擎身份闭环、启动面分派、判活/自愈引擎化、TUI 协议引擎化、上下文按引擎落盘、命名空间推断反转。

**涉及项目**：
- hermes-session-roles：persona schema 增 engine 字段（19 个 JSON，默认值兜底）
- session-launcher：ccs.py（CLI 增引擎参数）、core.py（StartOptions/启动 wrapper/环境断言/就绪判据）、tmux_ops.py（判活进程名、忙判据、composer 几何、提交确认、陈旧重启 comm）、ops/watchdog.py（双检进程扫描、重启透传）、ops/sentinel.py（engine 读写优先级反转）、ecosystem_health.py（cmdline 扫描按引擎）、routing/roles.py（指令文件按引擎落盘、同源渲染）
- session-pipeline：pipeflow/role_lifecycle.py（拉起/投递子进程调用透传引擎）、liveness.py（**只读不改**——D1 定沿用 ccs- 过滤）

**明确不碰**：codex_ops.py 与 codex 全部子命令（P6）；liveness.py 的前缀过滤逻辑（D1）；claude 分支既有判据文案与几何（P4）；任何生产会话（ccs-consumer/engineer/scout 等）。

**层内顺序（强制）**：第 1 层先行并单独验收 → 其后 2→3→4→5→7 可按依赖推进，但每层必须单独自验后才进下一层。理由见《计划》第四节：第 1 层是其余层的输入。

**验收（映射命题）**：
- P2：persona 默认 + CLI 覆盖 + 哨兵记录三处取证
- P1：opencode 会话走通启动→投递→判活→上下文→状态五链
- P3：kill opencode 进程 → 自愈重启后引擎不翻转
- P4：claude 全链对照 + claude 分支改动面证明
- P6：codex 冒烟不变（顺带证明回退兼容）

**自验硬要求**：
1. 每层改完立即验证（语法/冒烟），不堆完再验
2. 就绪判据落码前必须真机标定（候选特征见《计划》第 2 层），标定证据随交付上交
3. 测试一律用一次性角色名 oc-test-xx；测试完毕杀 tmux 会话、清 sentinel 与 workspace 残留；**探针脚本以文件为载体**（外层 shell 会展开脚本内变量并污染工作区——已实证）
4. 忙判据串必须整串精确匹配（两串互不为子串，但不得子串化放宽）

**交付物**：
- 变更说明：逐处「改了哪条链的哪个环节 → 为何影响 → 如何影响 → 为何能解决」（只讲逻辑不贴代码）
- 证据包：每条验收对应的真实捕获帧/输出摘录（含 opencode 会话拉起、投递、判活、不翻转、claude 零回归对照）
- 偏差清单：实现中与《计划》不符的事实或不得已的偏差，显式列出并给理由

## 三、工作包 T2（批次二：评估显式降级 + 全链路回归）

**范围（对应《计划》第 6 层 + 收尾验证）**：
- session-pipeline 转录消费点（role_lifecycle 转录解析、eval_checker、wf_lifecycle、意图分类器）：对非 claude 布局会话返回显式「未纳入评估」标记，标记进状态可见面；禁止默认通过或静默空集
- 全链路回归：按《计划》第五节证据协议跑满 P1–P6 六命题全套取证
- 降级点文档化：标注二期 opencode 转录接入的替换位置（不动调用语义）

**前置**：T1 通过三方审查后才启动 T2。

**验收（映射命题）**：
- P5：opencode 会话评估入口输出显式「未纳入」标记且状态面可见
- P1–P4、P6：全套回归证据闭环

**交付物**：同 T1 格式，另附六命题 × 证据索引总表。

## 四、共同纪律（两工作包均适用）

1. **事实基线**：《计划》第二节重验表；发现不符先上报，不就地改结论
2. **零回归举证责任**：凡触碰共享代码路径，实现方必须主动交 claude 等价性证据，审查方必须抽验
3. **命名与取值域**：engine 取值 "ccs"（claude，沿用历史名不改）/ "opencode" / "codex"（孤岛）；新代码一律经身份事实源取值，禁止新增前缀/进程名推断
4. **失败哲学**：失配、未知、缺证据 → 显式报错或显式降级；禁止静默猜测、禁止假闲放行
5. **报告口径**：只讲逻辑与证据，不贴代码；专业名词用《计划》术语表口径

---

## 五、三方审查交付格式（审查子代理 / 主代理使用）

逐维度输出：`维度 → 结论（通过/不通过）→ 证据核验记录 → 不通过项的精确位置（文件+环节）与理由`。
终审额外输出：放行/退回裁决 + 与 D1–D5 决策的符合性核对 + 残余风险登记（如探针残留、版本漂移监测建议）。
